# AI 模型路由方案

状态：建议方案，尚未接入模型
最后更新：2026-08-18

## 目标

在回复质量、响应时间和成本之间建立可测量的路由，不让所有消息默认进入最贵模型。

## 在线路径

1. 规则层先处理黑名单、明确命令、合规拦截和无需模型的固定问题。
2. 低成本模型完成意图、情绪、风险、业务类别和是否需要知识检索的结构化分类。
3. 对简单且高置信度的问题，低成本模型基于检索结果生成草稿。
4. 满足升级条件时调用高质量模型。
5. 回复通过政策校验；高风险类别进入人工确认。

## 建议升级条件

- 分类或答案置信度低于经过评估集校准的阈值。
- 投诉、退款、法律、医疗、财务、隐私或账号安全问题。
- 多轮上下文矛盾、用户情绪显著恶化或连续两次未解决。
- 高价值客户或高金额业务，但必须由业务服务提供判定。
- 检索结果不足、来源冲突或回答无法给出有效引用。

阈值不能凭感觉长期固定，应通过离线评估集和线上人工反馈调整。

## 每日批处理

低成本模型可每天处理：

- 会话主题和结果分类。
- 客户偏好、约束和待办候选抽取。
- 重复问题聚类、知识缺口和服务质量信号。
- 对话分段和高质量模型候选队列。

高质量模型只处理需要跨会话推理、候选记忆冲突合并、复杂知识切块和低置信度记录。批任务必须可重跑，并以日期、租户、会话和提示词版本建立幂等键。

## 模型接口要求

- 输入：任务类型、脱敏消息、允许的上下文、检索证据、预算、截止时间。
- 输出：结构化结果、置信度、引用、风险标签、是否建议升级。
- 审计：供应商、模型、提示词版本、token、缓存命中、耗时、估算费用、错误码。
- 隐私：供应商允许的数据范围按租户配置；禁止把完整数据库或无关会话交给模型。

## 费用控制

- 使用 token 上限、最大重试次数和每租户日/月预算。
- 历史上下文先检索再裁剪，不重复发送完整聊天记录。
- 对非实时摘要和合并使用供应商批处理折扣。
- 缓存稳定知识问答，但缓存键必须包含知识版本和权限范围。
- 当日费用异常时自动降低高质量模型比例并告警，不静默停服。
