# 旧服务端安全与配置风险

审计日期：2026-08-19

## 结论摘要

旧目录不能整包进入公开仓库。已确认存在敏感命名二进制、环境配置模板、大量 SQL 安装/升级脚本、第三方二进制压缩包和缺少来源证明的生成/安装产物。

本次没有读取或记录敏感二进制内容，没有输出配置值、匹配行、客户数据或密钥。高置信度文本特征扫描未发现 PEM 私钥、AWS AKIA、GitHub token 或常见 `sk-` 密钥格式；这不等于源码没有其他格式的真实秘密。

## 高风险文件类别

| 相对路径/类别 | 观察结果 | 处置 |
|---|---|---|
| `extend/sensitive_data.bin` | 11,600 bytes，内容未读取 | 禁止迁移；确认用途、来源和轮换要求 |
| `extend/sensitive_key.bin` | 48 bytes，内容未读取 | 禁止迁移；按真实密钥处理并轮换 |

| `extend/lib/protobuf/*.tar.gz` | Protobuf 工具/源码归档候选 | 不迁移二进制包；使用官方工具链重建 |

| `vendor/` | 45,266 个安装文件 | 禁止复制；从锁文件重建，但旧项目当前缺锁 |

## 配置键面

`.example.env` 可见的键名包括数据库连接、`API_KEY`、`PASSWORD`、`SIGN_KEY`、设备/RPA/微信端口、调试与任务超时配置。报告没有读取或保存等号后的内容。

59 个第一方 PHP 文件出现带默认参数的 `env(...)` 调用，需要逐项判断默认值是否只是安全常量。20 个文件命中“凭据类字段后跟非空字符串”的启发式规则，主要位于登录/配置验证器；这些是人工复核候选，不能直接判定为硬编码秘密。

## 可复现且不输出秘密的扫描

高置信度扫描只允许打开明确的文本扩展名，并只输出命中文件的相对路径。由于白名单不包含 `.bin`、`.sql`、数据库转储、抓包或压缩包，扫描不会为了判断文件类型而打开这些内容：

```bash
cd "$LEGACY_SOURCE_ROOT"
rg -Il \
  -g '*.php' -g '*.json' -g '*.env' -g '.example.env' \
  -g '*.ini' -g '*.yaml' -g '*.yml' -g '*.xml' \
  -g '*.js' -g '*.ts' -g '*.html' -g '*.css' \
  -g '*.md' -g '*.txt' -g '*.conf' \
  -g '!vendor/**' -g '!runtime/**' \
  '(-----BEGIN (RSA |EC |OPENSSH )?PRIVATE KEY-----|AKIA[0-9A-Z]{16}|gh[pousr]_[A-Za-z0-9_]{20,}|sk-[A-Za-z0-9]{20,})' .
```

本次返回码为 1，表示无匹配；扫描错误返回码大于 1，不能当作通过。

## 公开导入门

任何旧文件进入公开仓库前必须同时满足：

1. 所有权和许可证允许公开。
2. 不属于 `vendor/`、runtime、数据库/日志、客户数据、敏感二进制或来源不清归档。
3. 由人工或脚本确认不含真实秘密，并完成已暴露秘密轮换。
4. 只迁移当前任务需要的最小文件，而不是复制整个目录。
5. 暂存索引使用 `git grep --cached` 再次扫描。
