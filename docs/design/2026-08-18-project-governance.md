# AI 微信客服项目治理设计

日期：2026-08-18
状态：已批准

## 目标

为公开仓库建立一套能够被 Codex、Claude、Gemini、Cursor 和 GitHub Copilot 共同读取的项目规范，使任何一台电脑上的 AI 在修改代码前都能了解架构边界、当前任务、已经完成的工作和安全要求。

## 首批范围

本次只提交文档、AI 入口规则和安全忽略规则，不导入现有 PHP 源码、生成的 Protobuf 文件、数据库、日志或客户数据。

## 文档体系

- `AI_CONTEXT.md` 是跨 AI 的唯一规范来源。
- `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、Cursor 和 Copilot 文件只负责把不同工具引导到统一规范。
- `PROJECT_STATUS.md` 保存当前阶段、正在进行的任务和下一步。
- `CHANGELOG.md` 保存已交付变更。
- `docs/tasks/TASK-xxxx.md` 保存每个任务的目标、过程、决定、验证和交接。
- `docs/decisions/` 保存不可轻易逆转的架构决定。
- 架构、协议、数据、部署、AI、成本分别使用独立文档，避免单个文件无限增长。

## 推荐架构

采用渐进式重构：Go 负责设备连接和协议网关；现有 PHP 业务先保留；Python 负责模型编排、记忆抽取和知识图谱；PostgreSQL 保存业务及结构化记忆；Redis 保存连接状态、缓存和任务队列。

腾讯云 Agent Memory 通过项目自有的 `MemoryService` 接口接入。知识图谱在基础记忆稳定后再引入，优先评估 Graphiti 与 Neo4j。模型采用分层路由：低价模型处理分类、标签、基础摘要和每日批任务，高质量模型处理复杂对话、低置信度结果与长期记忆合并。

## 安全边界

仓库可以公开，但公开不等于允许公开业务数据。任何 AI 和开发者都不得提交密钥、访问令牌、账号密码、`.env`、数据库文件、日志、聊天记录、客户资料、设备标识或包含敏感字段的二进制文件。提交前必须检查暂存区。

## 工作流

1. 开始工作前阅读统一规范、项目状态和当前任务文档。
2. 为工作建立 `TASK-xxxx`，写明范围和验收条件。
3. 在独立分支修改，持续更新任务文档。
4. 运行与风险匹配的验证，记录命令和结果。
5. 更新项目状态与变更日志，通过 Pull Request 合并。

## 成本原则

成本估算必须注明消息量、日活率、上下文长度、高质量模型调用比例和数据保留期。服务器按连接数与消息吞吐分别估算；模型按输入、输出和批处理 token 分别估算。正式采购前重新核对云厂商和模型供应商价格。

## 不在本次范围

- 导入或重写现有 PHP 代码。
- 还原原始 `.proto`。
- 部署服务器或连接生产数据库。
- 调用真实客户数据测试模型。
- 实现 Go 网关、记忆服务或知识图谱。
