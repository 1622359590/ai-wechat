# 旧 APK 兼容的多设备鉴权设计

状态：待用户审阅
日期：2026-08-20
任务：`TASK-0006`

## 决策摘要

已分发的 AI 销售 APK 不受项目方控制，因此保留现有 TCP/Protobuf 协议和 `DeviceAuthReqMessage.Credential`。旧 PHP 代码证明 `Credential` 实际上是设备编号，不是秘密。新 Go 网关将使用独立 PostgreSQL 设备注册表进行允许、停用和到期判断，而不再使用单设备状态文件。

旧数据库只在一次性迁移过程中以只读方式使用。正式网关不包含旧库驱动、连接配置、表名或运行时降级路径。迁移完成后，旧库不参与鉴权。

## 已考虑的方案

### 方案 A：网关每次直接查询旧数据库

开发最快，但会把新网关与旧表结构、旧数据库凭据和旧业务可用性永久绑定。用户已明确新系统不能直接使用之前的数据库，因此拒绝。

### 方案 B：独立设备库 + 一次性迁移（选定）

新建 PostgreSQL 设备注册表，用一次性工具将旧库中的必要授权字段转换为新模型。运行时只依赖新库。该方案同时满足兼容性、独立性和后续管理需求，是本设计的基础。

### 方案 C：未知设备首次连接自动注册

不需要迁移，但任何知道或猜到设备编号的连接都可以抢先注册。这会重复单设备配对方案的根本风险，因此拒绝；未知设备必须默认拒绝。

## 兼容性边界

网关保持下列 wire 行为：

1. APK 建立 TCP 长连接。
2. APK 发送 `MsgType=1010` 的 `DeviceAuthReqMessage`。
3. 网关把 `Credential` 当作设备编号输入，但不写入日志或持久化明文。
4. 鉴权成功时返回 `MsgType=1011` 的 `DeviceAuthRspMessage.AccessToken`。
5. APK 在后续心跳和业务消息外层 `TransportMessage.AccessToken` 携带该 Token。

鉴于旧 PHP 忽略 `AuthType`，而已恢复枚举包含 `Default=0` 和 `DeviceCode=1`，兼容鉴权器接受这两个值，拒绝 `Username=2`、`InternalCode=3` 和未知值。真实设备验证将记录所见类别而不记录 Credential。

## 数据模型

### `devices`

| 字段 | 类型 | 约束与用途 |
|---|---|---|
| `id` | UUID | 新系统内部设备标识，主键 |
| `tenant_id` | UUID | 租户边界；首版使用单一默认租户 |
| `credential_fingerprint` | BYTEA | 32 字节，唯一，不可更新 |
| `credential_version` | SMALLINT | 首版固定为 `1` |
| `label` | TEXT | 运营人员自定义名称，不从 APK 信息自动生成 |
| `status` | TEXT | `active` 或 `disabled`，数据库 CHECK 约束 |
| `auth_expires_at` | TIMESTAMPTZ | 为空表示不设设备授权到期时间 |
| `last_authenticated_at` | TIMESTAMPTZ | 最后成功鉴权时间，不是心跳日志 |
| `created_at` / `updated_at` | TIMESTAMPTZ | 数据库管理时间 |

`credential_fingerprint` 不使用无密钥 SHA-256，而使用：

```text
HMAC-SHA-256(server_pepper, exact Credential bytes)
```

`server_pepper` 是服务器外部注入的 32 字节随机秘密，不进入数据库、镜像、Compose、命令行参数、日志或 Git。它降低数据库指纹被离线枚举的风险，但不会把设备编号变成真正的客户端秘密。丢失 pepper 会导致所有指纹无法查询，因此部署前必须建立服务器外加密备份。

### `device_admin_events`

只记录管理操作：内部设备 UUID、动作、操作者类型、原因代码和时间。不记录 Credential、指纹、Token、旧库主键或自由文本备注。

### 会话状态

首版不将会话 Token 写入 PostgreSQL。每个连接在网关内存中保留内部设备 UUID、随机 Token、到期时间和连接代数。服务重启后所有设备重新鉴权，这与旧 APK 断线重连模型一致。

## 一次性迁移

迁移工具是独立命令，不编译进网关运行路径。它通过受控环境变量获得旧库只读连接和新 PostgreSQL 连接，且只读取经现场映射确认的三类语义字段：

- 设备编号。
- 启用/停用状态。
- 授权到期时间。

迁移过程对设备编号立即计算 HMAC 并丢弃明文，不生成 CSV、SQL dump、调试输出或失败行文件。`--dry-run` 只输出总数、可迁移数、重复数和拒绝数。正式执行使用 `INSERT ... ON CONFLICT` 保证幂等，但不自动把新库中已停用设备重新启用。

实施时必须先在服务器上用只读 SQL 确认旧表和状态语义。旧表名、字段名、连接串和真实计数属于私有部署信息，不写入公开设计文档。

## 鉴权流程

1. 服务器在读取完整帧之前应用未鉴权连接总量限制、单 IP 并发限制和读取 deadline。
2. 首条有效业务消息必须是 `MsgType=1010`，重复鉴权关闭连接。
3. 校验 `AuthType`、Credential 非空、最大 4096 字节，且 Credential 必须是有效 UTF-8；不做大小写、空格或 Unicode 归一化，以保持与 APK 原始字节一致。
4. 计算 Credential HMAC 指纹并以等值索引查询 `devices`。
5. 未知、`disabled` 或 `auth_expires_at <= now()` 一律返回相同的外部失败行为，避免暴露设备是否存在。
6. 通过后生成 32 字节密码学随机 Token，有效期一小时；先成功编码响应，再将会话标记为已鉴权。
7. 在连接目录中以内部设备 UUID 原子注册新连接。如果同一设备已在线，新连接成功响应后关闭旧连接；不同设备互不影响。
8. 后续每条消息都以常量时间比较当前连接 Token 并检查到期时间。Token 过期、错误或缺失都关闭连接。
9. 定期和管理停用事件会关闭对应的在线连接；单实例首版由网关内存通知完成。

## 连接限制

首版以单网关、100 台以内为目标，使用进程内限制器：

- 未鉴权连接总数：50。
- 单源 IP 未鉴权并发：5。
- 单源 IP 鉴权尝试：每分钟 20 次，突发 5 次。
- 同一 Credential 指纹连续鉴权失败时指数退避，最长 15 分钟；内存中只保留带服务器临时密钥的短标识，不记录持久指纹。
- 已鉴权连接总数通过配置设置，首次部署为 150。

来源 IP 只用于进程内计数，不持久化也不写入日志。网关重启会清空限流状态；多实例阶段再迁移至 Redis。

## 管理面

由于当前没有可复用的旧后台，首个可部署版本提供本机受控 CLI，不开放公网管理 HTTP 接口。CLI 支持：

- 以明文 Credential 从标准输入添加设备；标准输入不回显，程序只持久化 HMAC 指纹。
- 以内部 UUID 列出设备状态、标签、到期时间和最后鉴权时间。
- 以内部 UUID 停用、恢复或修改到期时间。
- 用固定原因代码记录管理事件。

管理 UI 作为下一个独立任务，调用受鉴权的管理 API，而不直接连接 PostgreSQL。

## 失败处理与可观测性

- PostgreSQL 不可用时鉴权失败关闭，不使用本地配对文件或旧库降级。
- pepper 缺失、长度错误或无法读取时网关拒绝启动。
- 迁移工具遇到语义不明、非法时间或空设备编号时统计拒绝数并以非零状态结束，不输出具体行。
- 设备鉴权对外只暴露统一失败行为；内部指标区分 `unknown`、`disabled`、`expired`、`rate_limited` 和 `backend_unavailable`，不携带设备标识。
- 日志允许记录稳定事件类别、计数和耗时，禁止记录 Credential、HMAC 指纹、Token、完整源 IP、真实数据库连接串或消息体。
- `last_authenticated_at` 以最多每设备每小时更新一次的方式限制数据库写入。

## 验证策略

实施必须测试先行，并且每类行为先观察正确的失败：

- 数据库迁移和约束测试：唯一指纹、状态约束、到期语义、管理事件。
- HMAC 指纹测试：相同输入和 pepper 稳定，不同 pepper 不可直接复用，不接受无密钥 SHA-256。
- 设备库测试：active/未过期通过，unknown/disabled/expired 统一拒绝，数据库不可用时 fail closed。
- 协议测试：`AuthType=0/1`、`1010/1011`、Token 签发、后续心跳和现有旧 PHP 兼容 fixture。
- 连接目录测试：两个不同设备并行、同设备新连接接管、断线时不误删新连接。
- 限流测试：总量、单 IP、突发、退避、时钟推进和重启清空。
- 导入测试只使用合成旧库数据，验证 dry-run、幂等、不重新启用和无明文输出。
- `go test ./... -count=1`、`go test -race ./... -count=1`、`go vet ./...` 和容器 smoke 必须全部通过。

## 部署与回滚

1. 先部署独立 PostgreSQL，应用最小权限的网关数据库账号和独立迁移账号。
2. 在受控环境创建并备份 pepper，不在屏幕、终端回显或任务文档中显示。
3. 对旧库执行只读 dry-run，核对聚合计数后执行正式导入。
4. 以不影响现有网关的候选容器验证数据库连接、合成设备鉴权和资源上限。
5. 替换网关时删除单设备配对配置，但保留旧状态文件作为不加载的回滚证据，不删除其内容。
6. 首次只对受控来源验证真实 APK。扩大到多人公网连接前，必须单独记录对明文传输和设备编号可冒充风险的接受。

回滚恢复上一网关镜像和 deny-all 配置。回滚不恢复对旧数据库的运行时依赖，不删除 PostgreSQL 设备记录、pepper 或一次性迁移审计结果。
