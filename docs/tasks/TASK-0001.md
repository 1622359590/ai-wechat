## 背景

项目计划由 AI 长期协助开发，并可能在办公室和家里的不同电脑、不同 AI 工具之间切换。仓库必须自行保存完整上下文，不能依赖某一次聊天记录。

## 目标

- 建立所有 AI 共用的规范来源。
- 记录当前架构方向、前期调查事实、成本假设和后续任务。
- 规定每次工作都更新任务文档、项目状态和必要的变更日志。
- 为公开仓库建立默认的敏感信息保护边界。
- 通过独立分支和 Draft PR 交付首批文档。

## 范围

- Markdown 规范、状态、任务、架构和成本文件。
- AI 工具入口文件。
- `.gitignore` 安全默认值。

## 不在范围

- 旧 PHP 源码、生成的 Protobuf 文件或客户数据导入。
- Go、PHP、Python 生产代码。
- 服务器部署、数据库创建或模型 API 调用。
- 对现有业务进行功能修改。

## 验收条件

- [ ] `AI_CONTEXT.md` 成为唯一共享规范来源。
- [ ] 各主要 AI 工具入口均要求先读取统一规范、项目状态和当前任务。
- [ ] 架构、协议、数据、部署、模型、记忆和成本各有独立文档。
- [ ] `.gitignore` 覆盖密钥、环境文件、数据库、日志、客户数据和敏感二进制。
- [ ] 文档明确区分已确认事实、建议方案和尚未实现内容。
- [ ] 运行差异、忽略规则和敏感信息检查并记录结果。
- [ ] 使用独立分支提交并推送 Draft PR，不直接写入 `main`。

## 关键决定

- 仓库暂时公开，但业务数据和秘密始终不得公开。
- 首批提交只含文档和规则，不导入旧源码。
- 使用渐进式重构，不立即完全重写现有 PHP 系统。
- 统一规范集中在 `AI_CONTEXT.md`，工具入口保持精简。
