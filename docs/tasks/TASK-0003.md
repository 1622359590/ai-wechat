# TASK-0003：恢复并验证最小 Protobuf 协议

状态：已完成
负责人：Codex
开始日期：2026-08-19
最后更新：2026-08-19

## 背景

旧服务端没有发现原始 `.proto`，但仓库外存在 protoc 生成的 PHP 消息类和 `GPBMetadata` 描述符。TASK-0002 已确认首批五类消息、四字节大端长度头和四个消息类型值，并禁止把旧源码、敏感二进制或真实业务数据导入公开仓库。

## 目标

- 恢复可以独立编译的最小 Protobuf 3 协议。
- 固定消息名、package、字段编号、字段类型和首批枚举值。
- 生成不含真实标识或聊天内容的确定性合成帧。
- 使用 Go 动态描述符和旧 PHP 生成类验证双向解析及未知字段保留。
- 为 TASK-0004 的 Go 网关提供稳定协议输入，不提前实现生产 TCP 网关。

## 范围

- `TransportMessage`、`DeviceAuthReqMessage`、`HeartBeatMessage`、`FriendTalkNoticeMessage`、`TalkToFriendTaskMessage`。
- 首批 `EnumMsgType`、`EnumContentType` 和嵌套 `EnumAuthType` 的必要值。
- `.proto` 编译、描述符断言、合成 fixture、长度前缀和未知字段兼容测试。
- 只读调用仓库外旧 PHP Composer 依赖及生成类的本机兼容验证器。

## 不在范围

- 复制旧 PHP 源码、`vendor/`、`GPBMetadata` 或敏感二进制进入仓库。
- 生产 Go TCP 网关、真实设备连接、鉴权策略或断线重连。
- 恢复全部 225 个消息类型或所有历史消息结构。
- 使用真实微信号、设备标识、访问令牌、聊天内容、抓包或生产消息二进制。

## 验收条件

- [x] 五个 `.proto` 文件可以由 Go 测试中的 Protobuf 编译器加载。
- [x] package 固定为 `Jubo.JuLiao.IM.Wx.Proto`，字段编号和类型与旧 `GPBMetadata` 一致。
- [x] `HeartBeatReq = 1001`、`DeviceAuthReq = 1010`、`FriendTalkNotice = 1024`、`TalkToFriendTask = 1070`。
- [x] 每类消息包含正常、空/边界和未知字段三种确定性合成帧，共 15 个，不含真实数据。
- [x] Go 对全部 fixture 完成 decode → encode，并保留未知字段。
- [x] 旧 PHP 生成类对全部 fixture 完成 decode → encode，并保留未知字段。
- [x] fixture 的四字节大端长度等于 Protobuf 消息体长度且不包含帧头。
- [x] 任务、项目状态、协议说明和变更日志包含准确结果。
- [x] 暂存范围、测试、格式、链接、秘密和禁止文件检查通过。

## 风险与约束

- 生成类可证明 wire schema，但不能恢复原注释、保留字段和构建选项。
- 最小枚举只覆盖首批兼容测试；未知 enum 数字仍须按 Protobuf 3 规则保留。
- PHP 兼容检查依赖本机仓库外旧源码，通过环境变量传入路径；CI 不拥有该目录时必须明确跳过，不能伪装通过。
- fixture 只能使用固定的 `synthetic-*` 值和无业务含义字节。

## 依赖

- 仓库外旧源码只读目录，通过 `LEGACY_SOURCE_ROOT` 指定。
- Go 1.24 或更高版本。
- `github.com/bufbuild/protocompile v0.14.1`。
- `google.golang.org/protobuf v1.36.12`。
- 本机 PHP 及旧源码已有 Composer 依赖，仅用于兼容验证。
